# 01 · 产品功能与使用指南（AI PM 视角）

> **文档定位**：回答一个产品最基础、也最该先讲清的问题——**这个产品是给谁用的、能做什么、怎么用**。这是 PM 的起点，也是面试自我介绍时的第一段话。

---

## 一、产品定位（一句话）

> 面向 **求职者** 的 AI 面试陪练工具，用大语言模型（LLM）做 **简历分析、语音模拟面试、定向备考、面试日程管理**，帮求职者「看懂简历、练好面试、拿下 offer」。

---

## 二、目标用户与使用场景

C 端只有一类用户——**求职者**，但可以按求职阶段细分：

| 求职者类型 | 核心痛点 | 典型使用场景 |
|---|---|---|
| **应届生 / 校招生** | 没面试经验、简历单薄 | 简历分析 + 语音面试反复练手 |
| **转行者** | 缺目标岗位知识、心里没底 | 上传目标岗位面经 → 定向备考 |
| **跳槽者** | 想精准备战某家公司 | 上传该公司面试题 → 专项练习 |

> **PM 要点**：C 端产品虽然只有一类用户，但「谁在什么场景下用」要说清。这三个细分人群的共同诉求是「针对性练习」，而不是泛泛刷题。

---

## 三、核心功能地图（4 大模块）

```
AI 面试陪练（求职者）
├── 1. 简历分析        （上传 → AI 评分 + 修改建议 → 导出报告）
├── 2. 语音模拟面试    （选方向/JD → 实时语音对话 → 自动追问 → 评估报告）★ 核心
├── 3. 定向备考        （上传目标公司面经 → RAG 问答 + 生成题库 → 专项练习）
└── 4. 面试日程管理    （粘贴邀约 → 自动解析 → 日历 → 提醒）
```

---

## 四、各模块功能详解

### 4.1 简历分析模块

**解决什么问题**：求职者想知道「我的简历哪里写得好、哪里要改」。

**功能点**：

| 功能 | 说明 |
|---|---|
| 多格式上传 | 支持 PDF / DOCX / DOC / TXT / MD 等格式 |
| 异步分析 | 上传后后台异步分析，实时查看进度（待分析/分析中/已完成/失败） |
| AI 评分与建议 | 输出总分 + 5 个维度分（内容/结构/表达/项目/技能匹配），并给出优势与改进建议 |
| 去重与重试 | 相同简历（内容哈希相同）自动返回历史结果；分析失败最多自动重试 3 次 |
| 报告导出 | 一键导出结构化 PDF 简历分析报告 |

**使用流程**：上传简历 → 等待分析（轮询进度）→ 查看评分详情 → 导出 PDF。

![简历上传分析](https://oss.javaguide.cn/xingqiu/pratical-project/interview-guide/page-resume-upload-analysis.png)

### 4.2 语音模拟面试模块（核心）

**解决什么问题**：让求职者「开口练」，模拟真实面试的对话压力，而不是只会打字、查资料。

**功能点**：

| 功能 | 说明 |
|---|---|
| Skill 驱动出题 | 内置 10+ 面试方向（Java 后端、阿里/字节/腾讯专项、前端、Python、算法、系统设计、测开、AI Agent 等），每个方向有专属考察范围和难度分布 |
| JD 解析出题 | 粘贴岗位 JD，AI 自动解析并据此出题（自定义面试） |
| 智能追问 | 每题可配置多轮追问，模拟真实多轮问答 |
| 实时流式对话 | 基于 Qwen3 语音模型（ASR/TTS/LLM 统一），句子级并发 TTS，边生成边合成边播放 |
| 服务端 VAD | 自动断句，实时字幕（含中间结果） |
| 回声防护 + 手动提交 | 避免 AI 语音被误录入，也可手动提交 |
| 多轮上下文记忆 | 记住前面的对话，支持暂停/恢复、超时自动暂停 |
| 分阶段推进 | 自我介绍 → 技术考察 → 项目深挖 → HR 环节 |
| 异步评估 | 交卷后异步生成总分、逐题评价、优势与改进建议 |

**使用流程**：选方向（或贴 JD）→ 设难度/时长 → 实时语音对话 → 结束 → 异步评估 → 查看报告。

> **PM 要点**：语音面试的体验瓶颈要能**主动讲出「痛点 → 根因 → 下一步」三层**，这是 roadmap 能力的体现，而不只是"我知道有问题"：
>
> | 痛点 | 根因 | 下一步 |
> |---|---|---|
> | 端到端延迟偏高 | 服务端音频中转 | 换 WebRTC 直连 |
> | 无耳机时回声泄漏 | 服务端 VAD 误收 AI 语音 | 客户端 VAD 降噪 |
> | 弱网音频断续 | 无降级 | 断点续传 / 降码率 |
>
> 被追问"这项目还有什么可做的"，直接答这三条即可。

### 4.3 定向备考模块

**解决什么问题**：求职者想「针对某家目标公司 / 某个岗位」精准准备，而不是泛泛刷题。

**功能点**：

| 功能 | 说明 |
|---|---|
| 上传备考资料 | 上传目标公司的面经、面试题集、岗位 JD（PDF/DOCX/MD 等），自动分块向量化 |
| 定向问答 | 基于上传资料流式回答，AI 只依据这些资料，不打太极 |
| 自动生成题库 | 从资料自动生成主问题、参考答案、关键点、评分标准、追问 |
| 专项练习 | 从题库抽题组织专项面试，交卷后异步评估、给反馈 |

**使用流程**：上传目标公司面经 → 生成题库 → 定向问答 / 专项练习 → 看评估。

![问答助手](https://oss.javaguide.cn/xingqiu/pratical-project/interview-guide/page-qa-assistant.png)

> **PM 要点**：这是把 B 端「知识库管理」重新包装成 C 端「定向备考」的关键一步——求职者不关心「知识库运维」，只关心「我能不能针对目标公司练得更准」。

### 4.4 面试日程管理模块

**解决什么问题**：求职者收到多家公司的面试邀约，想统一管理、别错过。

**功能点**：

| 功能 | 说明 |
|---|---|
| 邀约解析 | 规则 + AI 双引擎，支持飞书/腾讯会议/Zoom 格式，自动提取公司、岗位、时间、会议链接 |
| 日历管理 | 日/周/月视图 + 拖拽调整 + 列表视图 |
| 状态流转 | 定时任务自动过期，手动标记待面试/已完成/已取消 |
| 面试提醒 | 可配置提醒，避免错过 |

**使用流程**：粘贴面试邀约文本 → 自动解析 → 生成日历日程 → 设置提醒。

![面试安排](https://oss.javaguide.cn/xingqiu/pratical-project/interview-guide/page-interview-schedule-list.png)

> **PM 要点**：日程管理和核心练习弱相关，属于锦上添花的模块。若重做 MVP，会把它往后放，把资源投到评估质量校准上。

## 五、端到端使用案例（求职者完整旅程）

以「求职者备战某家公司」为例，走一遍产品的最长路径：

```
1. 上传简历（PDF）
   → 异步分析，得到总分 + 5 维度分 + 修改建议
   → 按建议改简历，导出 PDF 分析报告

2. 语音模拟面试
   → 选择方向（如 Java 后端）+ 难度 + 时长
   → 实时语音对话，AI 自动追问
   → 结束，异步评估出报告，看短板

3. 定向备考（针对目标公司）
   → 上传目标公司的面经 / 面试题集
   → 生成专属题库，定向问答 + 专项练习

4. 收到面试邀约
   → 粘贴邀约文本 → 自动解析进日历 → 设置提醒
```

> **PM 要点**：这个旅程里有一个贯穿始终的模式——**「提交 → 异步处理 → 轮询 → 拿结果」**。简历分析、出题、评估全是异步的。讲产品时能点出这个统一交互模式，会显得你对产品理解很深。

## 六、统一机制：AI 产品的不确定性怎么消化

AI 产品有三类与生俱来的不确定性，这个产品用一套统一机制把它们消化掉——这是讲「异常路径设计」和「输出质量门禁」的核心素材：

| 不确定性 | 表现 | 产品怎么消化 |
|---|---|---|
| **慢** | LLM 任务几十秒到几分钟 | 异步状态机（待处理/处理中/已完成/失败）+ 前端统一「提交→轮询→拿结果」 |
| **会失败** | 分析/评估可能超时或出错 | 失败自动重试 3 次 + 相同内容哈希去重直接返回历史结果 + 失败给降级结果而非报错 |
| **输出不稳定** | LLM 结构漂移、字段多变 | 评估维度/逐题评价/追问用 JSON 字段存，不强行拆表 |

**产品设计的本质**：不追求 AI 永远快、永远对、永远稳定，而是**用统一的交互和兜底机制，把不确定性对用户的伤害降到最低**。简历分析、向量化、出题、评估四类长耗时任务共用同一套状态机，用户不需要理解背后的差异。

> **PM 要点**：这一条对应「统一交互」的产品策略——用户看到的是同一个"提交→等进度→拿结果"的心智模型，而不是四套各异的交互。

## 七、这个产品的差异化亮点（讲产品时用来「立住」的话）

1. **实时语音对话体验** —— ASR/TTS/LLM 一体化，句子级并发 TTS，服务端 VAD 自动断句，模拟真实对话压力。
2. **Skill 驱动出题 + JD 解析** —— 出题不是随机，而是「有方向、有难度、有参考知识库」的结构化出题。
3. **定向备考闭环** —— 上传目标公司面经 → 生成题库 → 专项练习，把「备考」做成可量化、可反馈的闭环，而不是泛泛刷题。

---

## 八、上线后如何定义成功（北极星 + 护栏）

- **北极星指标**：每周完成整场语音面试的人数——完成整场才算拿到价值，注册数、开始数都不是。
- **护栏指标**：评估失败率、首包延迟、单场 token 成本。
- **验证路径**：先在校招社群小范围放量，完成率和复练率达标再扩。

> **PM 要点**：这是"AI 产品怎么度量"的标准答案框架。被问"上线怎么定义成功 / 成本怎么算"，直接复用这三条即可，不必展开成独立文档。
