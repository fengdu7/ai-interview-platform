# 结束后的复盘与莉莉子的回答思路

这是依据作者题库编排的陪练反馈方法，不是招聘公司评分表。默认模拟和专项都在结束后统一给反馈；仅明确要求逐题教学才中途点评。反馈前读取 pitfalls.md、interviewer-criteria.md 及本次已练题目的相应章节。

## 输出结构

### 1. 本轮表现与覆盖

先简短总结实际表现，注明基于本次回答。用六大板块列出“已考察/部分考察/未考察”，日常AI习惯、产品sense、商业sense独立列明。每项结论要有实际回答依据；未考察不等于能力差。不输出录用概率，不宣称大厂标准或保过。默认不用数字分数。

### 2. 值得保留的地方与优先改进点

点出1—2项具体优点，最多3项优先改进。引用用户原话或具体行动，说明面试官可能卡在哪里、还会如何追问、需要补什么真实证据。专业直接但不替用户编故事，不把信息不足认定为造假。

重点看：是否答题、场景与业务目标、方案取舍、个人职责、上下游、评测口径、样本来源和标注、线上线下区别、成本/风险、失败复盘。选相关维度，不机械把全部套给每一道。

### 3. 莉莉子的差异化表达建议

先读 [莉莉子的差异化表达方法](lilizi-expression.md)，以作者补充的四项策略为主：
1. 尤其二面首次回答先提炼主干，再把展开方向交给面试官；具体追问时直接展开。
2. 从全局业务链路定位主要矛盾，让证据与取舍呈现方法论。
3. 从局部指标追溯商业价值：售后体验也可能支持正向交易，但区分价值机制、经营目标与已证实结果。
4. 行业洞察沿“选方向 → 讲重构 → 给判断 → 看指标”；竞品对比选主维度串联，再落到公司资源和策略。

每轮选相关的2—3项，结合用户原话说明“目前怎么讲 → 对应策略 → 可怎样重组 → 还需什么真实证据”。不是把常见错误清单换个标题，也不假装莉莉子本人现场点评。pitfalls.md里的指标、Bad Case、归因等作为证据检查，支持上述表达策略。

首轮介绍简洁且提供展开方向，不等于没深度；应结合后续追问回答评价。不强制每题都留话口，不为了商业思维编GMV因果。没有项目经验可以用真实Demo并标明范围。

### 4. 莉莉子的回答思路参考

选1—2道关键题，对照原资料解释作者如何拆题。写出对应本地参考文件与章节标题，能够追溯到资料；不可编造作者原话。示例：
- 喜欢的产品：basics.md「日常AI使用/习惯洞察」；从用户与场景定义、具体设计、取舍到不足和改进。不同用户的观点可不同。
- 技术选型：technical.md「为什么选RAG，而不是微调」；场景诉求 → 方案取舍和代价 → 验证。结合实际业务判断，不把RAG写成必选。
- 项目：projects.md「整体回答框架/项目真实性」；背景职责 → 数据定位瓶颈 → 阶段方案与取舍 → 分范围看结果 → 认知迭代与岗位契合。
- 业务设计：business.md；目标用户与场景 → 阶段优先级 → AI与人的分工 → 指标及边界。商业判断说明谁付费、为什么、成本是否覆盖，预测应有成立条件。
- 行业洞察：business.md「行业判断」及 lilizi-expression.md 第4项；选方向、讲角色/流程重构、给阶段边界、看验证指标，用具体案例支撑主张。
- 行为协作：behavioral.md；具体分歧 → 对齐标准 → 备选方案 → 决策机制 → 复盘沉淀。
- 反问：reverse-questions.md；按面试官职责，从业务、部门、公司选择真正关心的问题，并接对方的回答追问。

说明用户已经做到哪一步、缺哪一步；必要时给一段短改写。只使用用户确认的事实，缺数字写【待补充】，保留“未上线/预计/假设”。作者案例只能作为作者案例参考，不替换为用户履历。完整口述稿仅在用户需要时给出，不倾倒整篇模板。

### 5. 下一次怎么练

给2—3项可执行任务，例如把项目压缩为90秒并重答；补一张指标口径卡；准备一个失败样本；以真实任务比较两款工具。每项对应本轮一个缺口，给完成标准。最后指出适合重答的一题，不立即强制开启新面试。
