备注：

RAG可以理解成客服查手册：先找相关资料，再结合资料回答。

微调可以理解成客服做专项训练：通过样本调整模型在特定任务上的表现。

区别一句话： RAG 是每次现查，微调是提前练熟。

##### c）回答框架

场景诉求：我们要解决/定位的【问题】，场景的关键要求是【更新频率、来源或其他约束】。

方案取舍：因此优先选择【方案】，因为【匹配理由】；相比【另一方案】，需要承担【主要代价】。

效果验证：用【真实任务】检查【关键指标】；如果【问题仍存在】，再考虑【下一步优化】。

##### d）具体回答示例（假设企业客服辅助场景，大厂b端通用，很常见）

我们当时定位的核心问题是：客服查规则慢，业务规则又经常更新，所以需要能快速补充知识，同时让回答有据可查。

方案上优先选 RAG，因为业务侧改完规则，更新知识库就能很快生效，而且回答能带来源。微调更适合优化固定任务的表现，比如回复语气、话术格式，但它不会自动跟进规则变化，每次更新都要重新标注、重新训练，成本和周期都不适合客服这种高频变化的场景。RAG 的代价是需要持续维护知识库和检索质量。

效果验证上，我们用真实客服问题去测检索召回、回答准确性和处理耗时。如果检索没问题、资料也充分，但回答仍不稳定，先排查提示词和生成环节；确认是模型能力不足时，再评估微调。

##### e）本题型补充说明与题库

准备深度：

- 通用AI产品岗先讲清技术概念、适用场景、选型理由和代价。训练细节、消息协议等实现题归为“高技术向岗位选读”，是否深入以目标岗位JD为准。
- 开发岗面经可以拓展视野，不代表所有AI产品经理都要达到相同实现深度。
一、高频方向（基础概念）

- RAG 是什么
- Agent 和 Workflow 区别
- Prompt 怎么优化
- 什么是幻觉
- 上下文窗口怎么理解
- Embedding / Chunk 怎么影响召回
- 模型怎么选
二、专项拆解（有空再展开）

- RAG 召回差怎么办
- Agent 为什么不用 Workflow
- 多轮对话怎么做
- 怎么降低幻觉
- Prompt 改了没效果怎么办
- 工具调用失败怎么办
