# 莉莉子的差异化表达方法

来源：2026-10-13 作者在对话中补充的前三项策略，以及题库 business.md「行业判断」「竞品对比」、projects.md 的项目框架。以下示范句是为陪练整理的表达例，不冒充作者原话，也不是候选人已发生的经历。

## 1. 先讲主干，把展开方向交给面试官

尤其在二面、面对业务负责人做首次项目介绍时：先提炼项目目标、个人角色、主要矛盾、关键选择和结果，不把所有技术和过程细节一口气倒出。按问题范围用约1—2分钟讲主干，时长只是参考。

主干说完，可自然留出两个真实的深入方向，例如：
> 这个项目的主线大致是这样，里面主要有场景优先级和评测迭代两个部分，您对哪一块更感兴趣，我可以再展开。

选择权建立在已经回答问题的基础上，不能用这句话回避具体追问。面试官已问明确细节时直接回答，不再反问对方要听什么；也不每道题都套这句结尾。不是所有二面都一样，要根据对方职责和提问调整。

模拟规则：候选人讲完主干并邀请选方向时，面试官必须从其实际提到的方向选一个，接一个具体问题；不要因尚未主动倾倒细节就判定缺乏深度。后续能否展开才是证据。候选人只说空泛结论时，仍需追问而不是默许回避。

复盘看：是否先回答核心问题、能否提炼、留下的方向是否有真实内容、被选中后是否接得住。

## 2. 从全局定位主要矛盾，让方法体现在判断过程里

项目叙述：上层业务目标/完整链路 → 数据与调研发现的多个问题 → 判断哪个是主要矛盾及依据 → 为什么优先解决 → 方案分工和验证。

表达例：
> 我先看了完整的售后处理链路，发现既有操作流程断点，也有规则判断成本高的问题。结合发生频次和耗时，我们把重点收敛到【主要矛盾】，再分别判断哪些需要补流程、哪些适合AI辅助。

训练目标是讲出可复用的定位方法，而不是报“我用了某某方法论”。关注用了什么证据、为什么其他问题暂缓、方法如何导向决策，别让业务分析沦为铺垫后直接罗列功能。

模拟可依次追问：你为什么认为它是主要矛盾？排除了哪个替代解释？如果只能做一件事会怎么选？每轮只问一个。

## 3. 把项目目标连接到商业价值，解释指标背后的经营目的

作者强调：不要只看到局部数据指标，要思考项目最终怎样服务业务和商业化。所有项目都可以尝试追溯价值路径，但并非每个项目都有直接收入或已证明的GMV贡献；成本、留存、信任、风险控制同样可能支撑经营。

以售后体验为例：售后处理效率/规则清晰度 → 购买顾虑与信任 → 转化、复购或留存 → GMV及长期经营。它是需要证据验证的作用路径，不是默认成立的因果结果。GMV、收入、利润是不同指标，不混为一谈。

表达例：
> 售后完结时长是直接指标，更上层是改善服务体验、降低购买顾虑，支持正向交易。我们已经验证的是【直接结果】；它对转化或复购的影响，还需要【验证办法】确认。

复盘同时看：能否说明经营目的与机制；局部优化是否伴随成本/风险上升；是否区分已测结果、间接影响与目标假设。不要为了“有商业思维”把每个项目硬写成GMV增长，也不要把没有直接收入的基础能力判成没价值。

## 4. 行业洞察：有主张、讲变化、给边界、能验证

题库 business.md「行业判断」的四步：
**选方向（做取舍） → 讲重构（角色和流程变化） → 给判断（阶段与边界） → 看指标（验证）。**

回答大行业问题先限定具体业务场景。用真实案例或对比支撑观点，不罗列新闻，也不只说“AI提效”。说明哪个角色原来做什么、现在如何变化，当前哪里可行、哪里还不成熟，什么信号会让自己改判断。

可替换模板：
> 如果聚焦【具体业务】，我更看好【方向】，因为【依据及取舍】。它带来的变化是【过去的角色/流程】变成【新的角色/流程】，例如【可核实案例】。但目前受限于【条件】，我会先从【切入点】验证，重点看【2—3个指标】；如果【反向信号】出现，我会调整判断。

竞品对比另用原题库框架：选一个主维度（入口生态/用户心智/技术路线/商业化） → 用有依据的关系串联差异 → 结合目标公司的资源提出取舍。商业竞争题补充商业闭环，但不机械把维度关系当普遍因果。

保留框架，不要求候选人复述作者对具体产品的观点。原例中的市场与产品事实具有时效性，未核实时标为原资料观点，不能当当前事实。

## 如何用于反馈

复盘从这四项选本轮相关的2—3项，格式为“你目前的表达 → 对应策略 → 可怎样重组 → 尚需的真实证据”。没有观察到的策略标未观察到，不强行扣分。行业框架与项目策略按题型选择，不给所有回答硬套同一模板。
